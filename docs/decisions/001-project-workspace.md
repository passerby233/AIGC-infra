# 001 项目生命周期与统一工作台

日期：2026-10-02 · 状态：已确认

[返回决策索引](README.md) · [生命周期设计](../platform/project-lifecycle/001-project-lifecycle.design.md)

## 问题

多项目与多人研发需要串联目标、依赖、执行、验收与交付。逐个目标或运行维护 MD、重复登记进展和资产，会增加维护压力；多人项目还需要长期汇总各子能力的知识与证据。

## 决策

- 保留六阶段作为通用研发地图，在共享能力中增加跨流程项目生命周期管理、统一 DataViewer，并明确公共技术底座。
- 由统一 Project Workspace 展示研发入口与项目目标、里程碑、依赖、知识、实验、资产及多模态视图。
- Git 保存定义、验收要求、知识和确认决策；源平台保存运行事实；工作台使用可重建的汇总视图。
- 每个算法项目从 `project.yaml`、`README.md`、`AGENTS.md` 起步，复杂后按需拆分；普通运行自动关联，决策级实验补简短 MD。
- 使用稳定项目 ID，需要细分时增加工作项 ID；分别展示项目状态、自动验收结果和同步时间，证据不足显示未知，负责人确认结论与阶段推进。
- 各项目在自己的仓库维护定义，中央工作台自动汇总；大型项目可增加 Project Hub，长期汇总各方向知识并引用证据。

## 理由与影响

该分工保留简洁的研发入口，降低重复登记压力，复用现有执行与数据平台，并为多人知识沉淀和资产追溯提供统一关联。`AIGC_infra` 维护共用规范、模板和平台设计，实际项目记录留在各自仓库中。

影响全局架构、六个研发模块、共享能力目录与 Codex 指示。详细字段、接口、产品选型及验收门槛仍待后续定义。
