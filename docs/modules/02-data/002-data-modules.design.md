## 两层抽象

上层按职责分为获取、处理、存储与版本、预览、消费五个能力模块和工具入口，不以箭头或排列顺序表达真实数据流转。存储读写贯穿所有环节。下层「数据处理管线」单独展开上层「数据处理」模块的步骤依赖。模块之间以稳定媒体引用、样本 ID、结果版本和交付清单协作。

图中的承担方表示能力归属，具体团队和负责人在接入时登记。各模块可以独立执行、演进和验收。

## 获取与下载

- **承担方**：现有下载器及采集角色；下载交付改进对接 TCLOUD-12854。
- **输入**：来源清单、来源构造方法、采集规则版本和项目需求。
- **输出**：稳定 `raw_id`、原片存储引用、下载过程中写入的 MongoDB meta、失败记录及交付报告。
- **交付边界**：向存储登记原片和来源事实，处理模块读取已经交付且可访问的原片；下载成功与采集验收通过分别记录。

入口：[下载交付 Jira](https://jira.myhexin.com/browse/TCLOUD-12854) · [下载交付需求](001-data-engineering.requirements.md#下载交付完善需求) · [下载写库与恢复协议](001-data-engineering.design.md#下载过程中写入-mongodb-meta)

## 处理与管线

- **承担方**：avproc-ray 管线及各算子维护角色。
- **输入**：可读取的原片引用、来源 meta 和管线配置版本。
- **输出**：稳定 `sample_id`、原片与切片关系、媒体、指标、caption、条件资产和算子运行记录。
- **交付边界**：读取原片并把加工产物写回存储；处理运行成功与样本质量达标分别记录。SingleShot / MultiShot 的步骤依赖在处理层维护。

入口：[avproc-ray 代码](https://git-cc.myhexin.com:6443/10jqka/llm/aigc-05-04/avproc-ray) · [处理内部管线](003-data-processing.design.md) · [加工与质量协议](001-data-engineering.design.md#加工质量与条件协议)

## 存储与版本

- **承担方**：MongoDB、PASS / 数据资产能力和公共技术底座的存储能力。
- **输入**：原片、来源 meta、加工媒体、指标与标注引用；使用方提出的筛选、采样及划分规则。
- **输出**：可解析的媒体引用、元数据查询视图、不可变 Parquet 快照、版本 manifest、JSONL 与划分清单。
- **交付边界**：MongoDB 保存采集和加工事实；对象存储保存媒体与大体积特征；数据资产侧固定版本并登记，底座管理存储副本与访问。具体版本构建接口与 PASS 能力覆盖待核对。

版本构建在固定快照上执行筛选和分组划分，保存排除原因与分布报告。它属于数据资产交付，不并入镜头切分、质量分析等处理算子流程。复制到 OSS / CPFS 不生成新的逻辑数据版本。

入口：[版本构建与训练交付](001-data-engineering.design.md#数据集版本与训练交付) · [公共技术底座](../../platform/foundation/README.md)

## 预览与抽检

- **承担方**：统一 DataViewer 与现有数据平台的浏览能力。
- **输入**：指定版本或注明数据时间的查询视图、样本 ID、媒体、caption、条件与指标引用。
- **输出**：可追溯的多模态样本视图、抽检证据和问题样本引用。
- **交付边界**：以引用读取原片或加工样本，复用存储及数据适配；抽检结论交给处理角色或使用方确认，不另建媒体库。

入口：[统一 DataViewer](../../platform/data-viewer/README.md) · [平台接入协议](001-data-engineering.design.md#平台接入协议)

## 消费与使用

- **承担方**：训练、评测及其他模型研发使用角色。
- **输入**：固定 `dataset_id + dataset_version`、JSONL / manifest、split、可访问媒体和必需条件。
- **输出**：绑定确切数据版本的训练或评测运行、使用反馈与新一轮数据需求。
- **交付边界**：使用方定义数据需求、筛选规则和必需条件；资产侧构建版本；底座校验目标副本；训练与评测按固定版本读取，保留隔离的验证 / 测试集。

入口：[模型实验与训练](../03-training/README.md) · [评测与验收](../04-evaluation/README.md) · [数据规则与版本协议](../../../../algorithm-template/docs/data.md)

## 模块间最小交付约定

| 交付关系 | 交付内容 | 接收方核对 |
| --- | --- | --- |
| 获取 → 存储 | 原片引用、`raw_id`、来源和规则版本、下载 / 验收状态、报告 | 媒体完整性、来源可追溯、失败与未知项 |
| 存储 → 处理 | 可解析原片引用、来源 meta、管线配置 | 可读输入、稳定标识、原片与时间轴 |
| 处理 → 存储 | `sample_id`、加工媒体、算子结果与版本、来源关系 | 结果引用完整，执行状态与质量结论分开 |
| 存储 → 预览 | 样本视图、媒体、指标、标注与结果版本 | 同一样本和版本对齐，可回到来源 |
| 存储 → 消费 | 固定版本、快照摘要、JSONL / manifest、split | 无跨 split 泄漏、必需条件完整、目标副本可读 |

采集、处理、构建运行关联 `project_id`，必要时关联 `task_id`。生命周期层汇总交付证据，项目状态、自动校验结果和同步时间分别表达。
