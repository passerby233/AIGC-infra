# 05 可控性

用户问题：我希望视频中的某些内容按要求变化或保持，应该提供什么信号，模型如何使用它？

定位：按控制目标和信号组织导航，注入机制作为共享技术连接架构页；控制效果连接能力页。

## 子领域的技术内容

| 控制领域 | 信号与进一步解释 | 展开到机制时要写什么 | 评估问题/来源 |
| --- | --- | --- | --- |
| 语义 | 描述、动作、属性、编辑指令 | 文本编码与注入；引导强度是推理属性 | 对象与动作是否执行；[R33](../../research/sources.md#r33) |
| 身份外观 | 参考图、身份特征、对象或风格特征 | 特征提取、保留目标、主体绑定、个性化是否需逐对象微调 | 身份与整体服饰分别检查；[R28](../../research/sources.md#r28) |
| 空间结构 | 深度、法线、草图、区域、布局 | 信号维度与预处理；静态条件或逐帧序列；对齐方式 | 结构保持及变化自由度；[R02](../../research/sources.md#r02)、[R29](../../research/sources.md#r29) |
| 姿态 | 关节、骨架或驱动动作序列 | 姿态坐标、遮挡、身份与动作融合、时间对齐 | 姿态执行与自然性；[R27](../../research/sources.md#r27) |
| 轨迹 | 指定点/对象的运动路径 | 点到实体的绑定；稀疏约束与未控制区域；多个对象分离 | 跟随与对象身份是否同时成立；[R26](../../research/sources.md#r26) |
| 光流/运动向量 | 稠密帧间运动或压缩视频的运动表示 | 两者的信号来源与含义不同；运动估计误差如何传递 | 运动忠实度与遮挡；[R29](../../research/sources.md#r29) |
| 相机 | 旋转、平移、内参、轨迹或文字运动语言 | 坐标约定、轨迹参数化、相机条件模块；文字控制与数值控制区分 | 相机执行与场景几何；[R25](../../research/sources.md#r25) |

## 控制信号与注入机制分开

控制页回答“约束什么”，架构页回答“条件怎样进入网络”。可以共享拼接、交叉注意力、调制、Adapter、额外控制分支等技术节点，但不能把某一种注入方式写成所有控制方法的标准实现。

每个方法保存四组字段：控制目标、条件信号、注入/训练方式、执行效果。控制信号的存在只支持前三组中的相应事实，效果需要独立评测。

## 详情样例 A：相机控制

实体：`concept.camera-control`。

一句话：通过相机相关条件指定观看方向或运动，约束生成视频中的相机变化。

首屏并排展示轨迹示意与视频视角变化；明确“物体移动”与“相机移动”的不同。深入区分文字镜头语言、数值相机条件、相机轨迹编码和模块注入。

CameraCtrl 使用相机轨迹参数化和额外姿态控制模块，适合展示控制信号与模块设计的对应；具体参数化公式、坐标和实现需补读全文后填写。[R25](../../research/sources.md#r25)

详情还应说明：估计生成视频相机轨迹依赖重建或估计算法，其误差可能影响指标。

## 详情样例 B：身份控制

实体：`concept.identity-control`。

一句话：用参考条件帮助视频中的人物保持指定身份。

概览区区分人脸身份、身体外观、服饰和动作；它们不是一个指标。机制区以 ConsisID 为特定案例，说明参考条件提取与注入，避免泛化为所有身份控制都需要同样的频率方案。[R28](../../research/sources.md#r28)

与 `capability.subject-consistency` 的区别：本节点描述控制方法，能力节点描述结果是否一致。身份控制还可与图生/参考生成任务共同出现。

## 详情样例 C：多条件组合

实体：`concept.multi-control`。

示意条件：人物参考、姿态序列、相机轨迹、文本场景。教学图为每路标出对象、时间范围和进入位置；这是一种组合问题示例，不承诺所有模型支持这一完整组合。

详情展开缺失条件、区域绑定、条件强度、互相冲突及组合泛化。VideoComposer 提供组合条件的具体研究入口。[R29](../../research/sources.md#r29)

建议比较：各条件单独使用与组合使用的结果；固定其他因素，分别检查身份、运动和镜头执行。用户能看见“某一条件改善，另一条件退化”的权衡。

## 专题页面设计

主内容采用目标 → 信号 → 注入机制 → 如何检查四列。点击“轨迹”等信号展开可用表示，再从具体方法进入机制，不在同一层混排条件模态和模型名称。

筛选：目标、信号类型、静态/时变、主体/区域、单条件/多条件、是否需训练。方法与具体模型的兼容关系必须有版本证据。

关联：[任务合同](01-tasks.md)、[条件注入](04-architecture.md)、[控制忠实度与一致性](07-capabilities.md)。光流搜索结果显式区别 Flow Matching。

## 编辑优先级与验收

P0：身份、姿态、轨迹、相机、关键帧、多条件。P1：结构、风格、音频层级控制与条件组合评测。P2：音乐身体控制、精细事件时间和通用接口的实现级比较。

验收：控制目标、信号、注入和效果各有字段；相机和对象运动分开；多条件示例标为示意；没有用一个成功案例证明所有条件均受支持。
