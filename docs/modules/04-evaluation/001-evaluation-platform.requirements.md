## 目标与范围

基于现有 Prim Eval 补齐 AIGC 视频 / 音视频评测能力，使算法与业务能以多维评分比较模型，并从具体案例中发现差异原因。平台直接读取 PASS 共享存储已有文件，评测结果与项目、模型及基准版本关联。

本文件供后续 Codex 开发与接入时使用。本轮仅整理文档；现有界面观察来自本地快照，新增功能需求来自 TCLOUD-12853，补充协议与验收场景为草案，实际服务能力及接口需后续核对。

## 职责与 Infra 用途

04 负责执行 01 的基准与评分协议，组织单视频打分、自动指标、模型对照、案例分析和验收证据。该能力贯穿模型实验和推理优化，可复用已生成结果，也可基于固定基准调用已有生成能力。

人工多维评分回答“在哪个维度表现好或差”；逐行预览回答“具体表现在哪里”；汇总报表回答“差异覆盖多少案例”；自动指标与性能记录补充可重复检查的量化证据。评测平台维护这些任务与明细，统一工作台引用结果。

## 核心功能需求

### E01：直接读取 PASS 共享存储

评测平台按存储引用读取共享存储中的媒体及索引，无需评测员另行上传视频。样本清单关联 case、候选模型与媒体路径，平台通过存储适配解析可访问地址；不能要求用户浏览器直接读取服务器本地路径。

保留文件来源和访问权限。缺失或不可读取的媒体显示原因并计入异常数量，不能悄悄排除后仍宣称全部完成。具体根目录映射、索引格式和访问方式待 PASS 与平台接口核对。

### E02：单视频多维打分

算法与业务共同定义评价维度和分值解释，评测员对单个视频逐维打分，再用分数比较不同模型。该模式与现有匿名 A/B 偏好选择分开记录，不能将 A/B 选择自动换算成绝对分数。

维度可包括要求完成度、画面与视频表现、声音质量与听觉体验、音画对齐及参考内容保持；这些来自需求附图和模块目标，最终启用范围及量表待项目确认。保存评价维度的适用任务、分值范围、分数方向、评分说明和规则版本；某维度不适用时单独标记，不强制记 0 分。

评分记录关联 case、生成结果、维度 / 规则版本及评测员，保留备注与修订依据。维度更新产生新版本，历史评分仍按原规则解释；跨规则版本的分数不能未经说明直接合并。盲评、多评测员分配、重复评分合并和一致性检查的方式待定。

### E03：评测 case 对比预览与差异筛选

评测完成后提供对比预览页。每行以同一 case 为单位，展示 prompt、条件素材及所选模型的视频、维度分数和备注；通过稳定 ID 对齐，不按文件排列顺序推断配对。

支持选择 A / B 模型与评价维度，筛选“A 在该维度好于 B”的案例，例如同口径下 `score(A, d) > score(B, d)`，并查看 B 在该维度的具体视觉 / 音频问题。也应可查看反向差异、并列及未完成项；阈值差值、排序与分页细节为后续交互设计。

比较使用相同 case、维度与评分规则版本；多人评分的归并方式须事先确定。仅一侧有分数或该维度不适用时单独显示，不当作已成立的优劣结论。模型身份可在评审阶段匿名，算法分析页通过授权映射回真实模型版本。

### E04：后期自动化报表

此项按 Jira 定位为后期进阶功能。报表可参考附图展示模型 / 维度分数、分数分布、各模型 case 数量和问题类别，并从图表进入逐行明细。

同时展示有效评分数、未评分 / 不适用数、生成失败和媒体异常数，注明基准、规则版本与汇总方法。模型对比默认注明共同可比较的 case 范围，覆盖率不同不能只依据整体均分宣布优劣。总分权重、是否采用均分、置信区间等统计方案均待确定；保留原始评分供核对。

### E05：自动指标与性能证据

这是原模块能力的补充接入要求，不是 TCLOUD-12853 已明确要求的新增功能，也不表示 Prim Eval 已实现。根据项目接入生成质量指标及耗时、显存、成本，保存计算工具 / 配置版本和执行来源。

运行或计算失败、缺失值与有效指标分别表达。人工评分、自动指标、人工评分汇总和性能结果分别呈现；项目未定义综合公式时不自行混成总分。改变生成配置的推理优化需回到相同或明示修订后的协议重新评测。

## 项目关联与边界

建议关联链为 `project_id → task_id（可选）→ eval_run_id → case_id → generation_id → 评分 / 指标 → 报告版本`。这些是逻辑标识，实际字段名通过已有平台映射；同一 case 的不同模型、随机种子或重复生成分别保存结果引用。

评测运行固定基准版本、真实模型 / Checkpoint、生成配置与评分规则版本。项目 `project.yaml` 引用验收规则与所选证据；普通评测由源平台自动关联，改变技术或交付决策的结果另补简短结论文档。

原始评测记录由评测平台维护，生成日志由执行平台维护，媒体由 PASS / 存储维护；工作台采集摘要与版本引用。DataViewer 负责复用媒体对照和案例浏览，评测平台负责评分任务、评分明细及业务统计，两者对齐同一 case 和生成结果。

评测运行状态、评分覆盖率、自动验收结果、最近同步时间、负责人确认的项目结论分别展示。证据不足或不可访问时显示未知及原因；任务完成不直接推进项目状态。性能优化和发布由 05 负责，模型训练由 03 负责，数据补充与隔离由 02 负责。

## 网页开发约定

后续 Codex 开发统一工作台网页时，在 evaluation 模块详情页工具入口区提供“[打开 Prim Eval 评测平台](http://117.50.195.94:2051/)”跳转链接，目标固定为 `http://117.50.195.94:2051/`。本轮不开发网页或修改现有评测服务。

入口旁可展示平台用途与需求文档。项目评测卡片展示基准 / 模型版本、评测进度、报告与原始证据入口；任务 / 报告深链接和同步接口待确认，不编造 URL 规则。平台可访问性由实际运行时判定，保存快照不代表服务当前在线。

## 验收标准

以下为后续开发验收场景草案，本轮未执行平台测试。

| 能力 | 可观察的验收结果 |
| --- | --- |
| E01 | 注册共享存储媒体引用后可预览，无须再次上传；访问失败有明确原因与计数 |
| E02 | 单视频可按多个维度评分并保存备注；维度修订后历史记录仍能回溯原规则；不适用与未评分可区分 |
| E03 | 同 case 的 A / B 输出正确对齐；指定维度筛选出的案例与评分明细相符，缺失分数不产生错误优劣结论 |
| E04 | 报表的分数、计数与原始明细一致；比较范围、覆盖率及规则版本可见，图表可返回案例 |
| E05 | 指标与性能记录能追溯工具版本和生成运行，失败计算不作为有效分数 |
| 项目关联 | 任一报告可回到项目、基准、模型、生成配置和评分规则；自动结果与负责人结论分开 |
| 网页入口 | evaluation 页面包含正确的平台跳转链接；已知报告 / 任务来源有对应入口 |
