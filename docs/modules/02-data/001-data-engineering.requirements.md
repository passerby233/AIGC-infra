## 目标与范围

为 AIGC 视频与音视频生成研发提供从下载交付、原始数据入库、镜头 / 场景切分、质量分析、标注和条件特征提取，到成品数据集筛选与训练取用的完整数据链路。后续 Codex 应基于现有 infra 完善协议与接入能力，保留现有媒体和数据库资产。

覆盖 SingleShot 与 MultiShot 数据，以及音视频同步、多语言、参考图 / 参考音色、关键帧等条件数据。具体项目按训练需求启用能力，不要求所有样本执行全部算子。

本轮产出为开发方案文档。MongoDB 下载 meta 的选型及写入时机已由用户确认；其他新增字段、状态协议、平台接口和验收场景为设计输入，尚不表示对应能力已实现。

## 现有规范基线

以下是参考资料中记录的约定，部署覆盖情况需后续接入时核对。

### 数据流转与存储

| 环节 | 现有约定 |
| --- | --- |
| 下载 | 各集群下载后汇总至乌兰察布；原规范要求传输完成后删除其他集群数据 |
| 处理 | 乌兰察布为主，4090 等低成本算力加工，结果写入 MongoDB |
| 数据库 | `raw_data` 保存源数据，`vidproc` 保存切片；collection 按数据类别或数据源组织，具体映射待核对 |
| 成品整理 | 从 MongoDB 导出 Parquet，按业务筛选得到 JSONL 样本索引 |
| 训练取用 | 成品媒体和索引同步至亚特兰大 OSS，必要时加载 CPFS |

后续方案应区分“数据版本”和“存储副本”：跨集群复制不产生新逻辑版本；清理源副本须以目标完整性确认及保留策略为前提，由公共底座承担执行。

### 下载要求与分包

通用要求：无内嵌字幕、有音频、FPS 在 23 以上。参考下载规范的类别门槛如下；这些是采集要求，不能直接当作所有切片的质量阈值。

| 类型 | 最低分辨率 | 最低时长 | 最低码率 |
| --- | --- | --- | --- |
| 电影 | 1920 × 1080 | 20 min | 2000 kbps |
| 电视剧 | 1920 × 1080 | 15 min | 2000 kbps |
| 短剧 | 1920 × 1080 | 20 s | 1000 kbps |
| YouTube / H.264 | 1920 × 1080 | 20 s | 2400 kbps |
| YouTube / VP9 或 AV1 | 1920 × 1080 | 20 s | 1800 kbps |

分包使用六位数字 ID。电影每 1000 个视频一包；YouTube 每 1000 个视频 ID 一包，ID 目录内保留媒体和来源 JSON；电视剧按 1000 季分包并尽量归拢同一剧集。短剧规范文字为每 100 部一包，示例却写 1000 部，需确认后配置，不能据示例固化。

画面拒收项包括明显模糊、曝光细节丢失、压缩失真、严重非剧情遮挡、硬字幕 / 台标 / 水印，以及超出类目要求的抖动。明确标注 AI 合成的内容按下载规范拒收。原文有效的内容要求作为采集规则引用，删除线条款不视为生效规则；自动检测尚不能覆盖的要求须留抽检或人工判定入口。

Stage0 文档另有较低分辨率 / 码率、`fps ≥ 23.09` 等过滤描述，且有“码率 ≥ 720p”的单位混写。本方案优先记录专门的下载规范，冲突列入待定；后续统一字段、单位与适用阶段后才能形成可执行规则。

### 处理与数据取用

现有资料记录入库、媒体属性提取、HDR / SDR 预处理、镜头 / 场景切分、切片导出、去重、视频与音频质量、音视频同步 / 语义分析，以及标注和参考特征等能力。主要代码入口为 [avproc-ray](https://git-cc.myhexin.com:6443/10jqka/llm/aigc-05-04/avproc-ray)，本轮依据文档设计，未检查仓库实现。

切片使用挂载根目录之外的相对路径，保留来源原片与时间范围；数据以 MongoDB 查询、Parquet 索引或已有 JSONL 取用。SingleShot 与 MultiShot 总图的 Stage3 / Stage4 含义不同，部分特征提取页为草稿，后续以功能名称及管线版本标识步骤，不用裸阶段编号确定接口。

## 下载交付完善需求

[TCLOUD-12854：AIGC 数据下载交付物完善需求](https://jira.myhexin.com/browse/TCLOUD-12854) · [本地 Jira 快照](<../../../../asset/[TCLOUD-12854] AIGC数据下载交付物完善需求 - 手机Jira.mhtml>)。

**状态：已提需求，开发中；已敲定方案：使用 MongoDB 管理下载数据 meta，在下载过程中写入。** 状态按本次用户确认记录，本地快照仅提供需求内容。

需求针对单视频 JSON 分散存放、后续扫盘汇总成本高、失败后继续下载产生重复文件的问题，要求：

1. 下载过程中动态维护统一 meta，记录成功 / 失败、来源、存储路径及常用筛选属性。
2. 可恢复失败任务，复用已成功记录，避免续传时生成重复媒体及重复统计。
3. 下载完成交付分布统计，例如不同类别下载数量；失败与未完成数量须与成功数量分开。
4. 交付可访问的元数据引用，可使用数据库地址；提供长宽、时长、FPS、码率等筛选字段及其缺失说明。
5. 交付来源构造方法：关键词、频道 / 来源范围、过滤方式、候选 URL 的形成过程及规则版本，可引用独立文档。
6. 分辨率、码率、分包等继续遵循下载规范；交付明细包括数据集名称、简介、PASS 链接、相对目录、数量、大小、交付时间。

meta 和分布报告应由相同的记录范围生成。单视频 JSON 可作为来源附件保留，统一汇总不再依赖下载结束后重新扫描全部 JSON。MongoDB 写入细节、幂等键和恢复协议见对应设计，属于本轮设计草案。

## Infra 能力需求

| 编号 | 能力 | 必须表达的行为 / 产物 |
| --- | --- | --- |
| D01 | 下载与交付接入 | 在线写 meta、状态跟踪、失败恢复、稳定来源标识、交付报告及来源方法 |
| D02 | 入库与兼容 | 复用 `raw_data` / `vidproc`；旧 JSON 与扫盘记录可补录，标明来源和字段缺失；统一单位与媒体引用 |
| D03 | 切分与溯源 | SingleShot / MultiShot 配置可区分；原片、scene、shot、切片时间范围和音频对应关系可追踪 |
| D04 | 质量与去重 | 保存分数、重复关系和规则版本；算子执行成功与样本质量通过分开，失败 / 缺失不能当作通过 |
| D05 | 标注与条件配对 | 保存 caption、标注模型 / 提示词版本；按需关联参考图、音色、关键帧、编码器特征与对应角色 / 时间 |
| D06 | 数据集构建 | 从固定元数据快照筛选、划分，产出固定版本与样本清单；记录排除原因和分布变化 |
| D07 | 训练交付 | JSONL 引用可读媒体、caption 和必需条件；OSS / CPFS 副本完整性可核对；训练记录引用确切数据版本 |
| D08 | 浏览与项目关联 | 复用 DataViewer、PASS 与生命周期接入，显示数据量、状态、分布、来源证据及同步时间 |

质量门槛与采样配比由项目数据规则承载。现有筛选阈值页可作初始候选，不能把示例分数直接设为所有数据的硬门槛。未知、失败、未运行、质量拒收应分别可查询。

## 验收标准

下表是供后续开发使用的验收场景草案，不表示本次已运行或验收通过。功能一致性要求可明确检查，吞吐、抽检数量、检测准确率及质量门槛待项目确定。

| 对应需求 | 验收场景 | 证据 |
| --- | --- | --- |
| D01 | 下载中可查询已登记来源、状态和已有 meta；成功项有有效媒体引用，失败项有失败原因 | 同一下载运行的数据库记录、媒体校验与事件日志 |
| D01 | 中途停止后恢复，同一来源不会新增成功媒体或重复统计；失败尝试历史仍可追踪 | 停止 / 恢复前后的来源计数、文件引用及尝试记录 |
| D01 | 类别计数、成功 / 失败 / 未完成计数与 meta 相符，报告可回溯来源构造方法和 PASS 交付明细 | 固定范围的交付报告和元数据引用 |
| D02 | 历史字段、路径与单位经映射保持含义；未知字段显式缺失，不伪造成功状态 | 迁移样例对照及核对报告 |
| D03 | 任一切片可追溯原片与边界；scene 内 shot 时间范围合法，音视频及条件引用对应同一样本 | 固定样例、边界校验、DataViewer 抽检 |
| D04 | 成功但低质量、运行失败、未运行三种样本产生不同结论；只重算指定算子不覆盖无关结果 | 算子结果、筛选规则及重算前后对照 |
| D05 | caption 与条件的模型 / 提示词 / 编码器版本可追溯；必需条件缺失样本不能进入对应训练清单 | 标注与条件完整性校验、浏览抽检 |
| D06 | 固定快照与规则重复构建产生相同成员；按原片 / 同作品 / 重复组划分后无跨 split 泄漏 | 样本清单摘要、分组划分检查报告 |
| D07 | 已发布版本不会因 MongoDB 后续更新改变；目标副本的清单、媒体数量和校验值对应版本 | 版本 manifest、传输核对与训练读取样例 |
| D08 | 浏览与工作台能回到源样本、运行和交付版本；项目状态、自动校验结果、同步时间分别呈现 | 接入样例与源平台证据 |
