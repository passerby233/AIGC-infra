# 07 能力、核心问题与评估

用户问题：视频哪里做得好或不好，怎样识别问题，哪些方法可能改善，如何验证？

定位：以失败现象连接技术与证据。能力是希望实现的表现；指标和基准是观察能力的工具，二者分开组织。

## 子领域的技术内容

| 问题 | 用户可观察的失败 | 测量与研究方法 | 候选技术关联 |
| --- | --- | --- | --- |
| 视觉质量 | 模糊、重复纹理、人体变形 | 细节/伪影检查、图像质量指标、人类评价 | codec、数据过滤、后训练 |
| 语义执行 | 对象缺失、属性错绑、动作顺序错误 | 拆分提示要求；对象/关系/动作分别检查 | 文本融合、caption、偏好训练 |
| 运动质量 | 静止、僵硬、突变或动作未完成 | 动态程度与自然性分别测量 | 时空连接、运动数据、运动控制 |
| 时间一致性 | 闪烁、纹理变化、跨块跳变 | 局部和跨段检查；真实运动与错误变化消歧 | 时空建模、重叠窗口、编解码 |
| 主体一致性 | 换脸、衣着漂移、物体消失 | 人脸/视觉特征与人类判断；遮挡前后检查 | 身份条件、参考特征、记忆 |
| 几何一致性 | 转动后结构改变、错误遮挡 | 多视角或重建辅助；估计工具误差需说明 | 相机条件、空间表示、跨视角约束 |
| 物理常识 | 穿透、重力错误、材料交互不合理 | 指定交互场景、人工判断、专项评测 | 数据、状态建模、训练目标；均须实验支持 |
| 长程叙事 | 人物或场景长期漂移，事件不连贯 | 多时长测试；跨镜头与连续长视频分开 | 规划、上下文延展、记忆、长序列调优 |
| 控制忠实度 | 轨迹、相机或姿态没有执行 | 条件与结果比较；每路及组合同时检查 | 控制模块、信号对齐、条件融合 |
| 音画对应 | 口型错位、声音与事件不对应 | 时间对齐、人类评价；不同任务协议分开 | 音频条件或联合音视频建模 |
| 效率资源 | 首段等待久、长视频 OOM、解码慢 | 明确计时边界、输入规模、精度和硬件 | 缓存、蒸馏、压缩、稀疏、并行 |

本表中的技术关联是研究与阅读方向，不是“采用该技术必然解决问题”的结论。主要能力维度由 [R37](../../research/sources.md#r37)、[R38](../../research/sources.md#r38)、[R39](../../research/sources.md#r39) 支持；音频任务参考 [R30](../../research/sources.md#r30)、[R41](../../research/sources.md#r41)。

## 指标与基准详情规范

| 对象 | 要展示什么 | 边界 |
| --- | --- | --- |
| FVD | 比较生成与参考视频分布；特征、采样、样本量、数值方向 | 不作为单视频的身份、物理或控制正确性证明 |
| VBench | 维度、提示集、计算方式与人类偏好核验 | 总分旁保留分项；协议不同不能直接排名 |
| VBench-2.0 | 更深的忠实度维度及评估方法 | 与原 VBench 的分数不可当作同一量表 |
| VideoPhy | 物理活动、材料交互、语义与物理判断 | 不把专项通过率视为全面世界模拟能力 |
| 人类评价 | 问题、盲评、随机顺序、样本、评审一致性 | 偏好选择与客观正确性可分开询问 |
| VLM/专家评估 | 模型版本、提示、采帧、输出格式和人类校验 | 评估器本身可能误判；不可省略验证过程 |

依据：[R40](../../research/sources.md#r40)、[R37](../../research/sources.md#r37)、[R38](../../research/sources.md#r38)、[R39](../../research/sources.md#r39)。表中的协议完整性要求是本设计提出的记录规则。

## 详情样例 A：主体一致性

实体：`capability.subject-consistency`。

一句话：同一人物或对象在时间、视角和遮挡变化中保持可识别的身份与属性。

首屏展示一组来自不同时间的帧位，标出需要检查的人脸、服饰和物体特征。不能用“画面完全不动”作为一致性理想样例；同时检查动作和视角变化。

问题区链接身份控制和参考生成；评测区链接对应维度，注明人脸和一般物体的评估方式可能不同。提出检查方法，不在没有实验时填写任何模型排名。

## 详情样例 B：物理合理性

实体：`capability.physical-consistency`。

一句话：视频中的交互、运动和材料变化与指定场景的物理/常识要求相符。

用“斜面上的物体运动”“物体接触与碰撞”“固体与液体交互”解释判断目标。VideoPhy 研究物理常识，VBench-2.0 包含物理和常识等维度。[R39](../../research/sources.md#r39)、[R38](../../research/sources.md#r38)

详情严格分开视觉逼真、文字要求执行与物理合理。问题到方法的连接标为“研究方向”，不宣称画面逼真或某个单一分数就证明了世界模型能力。

## 详情样例 C：效率

实体：`capability.efficiency`。

显示四项：首个可播放片段延迟、持续生成速度、完整任务端到端耗时、峰值显存。帧率注明是生成吞吐还是视频播放 FPS。

深入区把条件编码、去噪、通信、解码、写盘是否计入逐项列出；流式生成还需记录交互响应和长时间资源占用。方法卡片链接少步、缓存、量化与并行，但不将论文中的单一硬件数字展示为统一系统速度。

## 详情样例 D：评测协议

实体：`benchmark.vbench`；可比较 `benchmark.vbench2` 与 `benchmark.videophy`。

首屏回答“测什么”，再展示“怎样测”。每个结果保存模型版本、输入任务、提示是否扩写、生成设置、随机种子、样本数量、评测器版本和聚合规则。不同条件的结果作为不同实验记录，不能悄悄混入同一排行。

## 专题页面设计

主内容采用失败现象 → 解释 → 如何检查 → 相关方法的渐进阅读。每个能力页提供失败案例位与对比位；后续素材需有出处和实验条件。

筛选：能力目标、短片段/长视频/跨镜头、自动/人工评测、任务和输出模态。默认先展示分项能力，不优先展示一个综合排行榜。

跨视角跳转使用明确标注：相关机制、研究该问题的方法、评估该能力的工具。总体美学、运动量、控制准确性等可能存在权衡，要保留多维比较。

## 编辑优先级与验收

P0：语义、运动、时间/主体一致性、效率、VBench/FVD 的边界。P1：物理、几何、长程、控制忠实度、VBench-2.0/VideoPhy。P2：音画专项基准、完整跨镜头评测、可靠性与内容安全的专业评测。

验收：能力与指标是不同实体；每项指标有适用范围；相似度不替代物理或控制判断；评测协议可追溯；不存在缺少设置的性能排名。
