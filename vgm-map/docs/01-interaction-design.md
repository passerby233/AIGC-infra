# 页面与逐层展开交互

## 1. 四种内容状态

| 状态 | 主内容 | 用户下一步 |
| --- | --- | --- |
| 总览 | 七个视角的一句话说明、适合谁、典型问题 | 选择视角或搜索 |
| 领域概览 | 定义、边界、下一层子领域、区别表 | 展开一层或查看子领域 |
| 技术详情 | 简明解释、原理、设计选择、局限、代表工作 | 继续深入或跨视角阅读 |
| 模型/方法/评测详情 | 类型专属字段和来源 | 查看采用的技术及对应问题 |

任一非叶子节点都有概览。用户即使停留在第二层，也应获得一段完整解释，而不是只看到目录。

## 2. 布局

桌面端使用左侧 280–320px 大纲和右侧正文；数字是设计起点，后续以中文标题和实际屏幕检验。正文保持舒适行宽；相关节点放正文末尾，关系较多时使用侧边抽屉。顶部包含站名、搜索、总览入口与当前位置。

初始大纲显示七个一级入口，全部收起。总览中的七个入口与大纲对应，不增加重复的分类系统。

移动端使用单列正文；“大纲”按钮打开抽屉，面包屑可横向滚动，关闭抽屉后保留选中项。宽比较表改为可逐条阅读的属性组。

## 3. 展开与选择是两种动作

点击箭头只展开下一层，不更换正文；点击名称选中节点并展示正文。选中父节点时，正文同时显示一段概览和下一层入口。叶节点不展示假箭头。

不自动关闭其他分支，允许比较；提供收起全部、展开当前节点下一层和恢复浏览状态。默认不提供一键展开整个库。

选择节点时大纲定位到它；只在选中项不可见时滚动大纲，避免每次点击都改变位置。面包屑点击返回祖先，浏览器后退恢复展开状态与正文阅读位置。

未来页面地址同时表达 entity_id 与导航上下文。主体地址稳定，视角路径只是上下文；不让一个技术因多个入口出现多个版本。

## 4. 详情阅读深度

默认展开：一句话解释、要解决的问题、最简流程、子领域入口。

默认收起：数学推导、训练细节、实现设计、失败案例、论文与代码说明。每个折叠节有能独立理解的标题，例如“为什么历史 KV 可以复用”，而不是“更多”。

首屏用中文解释，英文名和缩写作为副标题。公式有符号解释，并区分视频时间与去噪时间。正文中的关联词可以跳转，但不把每个专有名词都变成链接。

## 5. 七类专题的专属展示

| 视角 | 建议主图/比较方式 | 关键误解检查 |
| --- | --- | --- |
| 任务 | 输入 → 保留条件 → 输出 | 参考图不一定是第一帧；输出音频与输入音频分开 |
| 范式 | 生成过程分步图、统一比较表 | DiT 不列为独立范式；流与扩散的关系有说明 |
| 时序 | 帧/块时间轴、依赖连线、上下文范围 | 区分生成顺序、去噪步、编码器因果性 |
| 架构 | 视频 → 编码 → patch → 骨干 → 解码 | 模块示意不伪装成所有模型的统一实现 |
| 控制 | 目标、信号、注入位置、执行结果四列 | 相机运动与物体运动分开；条件组合可能冲突 |
| 训练推理 | 数据到部署流程、方法对照、成本字段 | LoRA 是参数化选择；CFG 不是微调；缓存种类消歧 |
| 能力 | 失败现象 → 检验方式 → 候选方法 | 美观不等于物理正确；指标不等于能力本身 |

所有主图都属于后续制作计划。本目录不生成可运行网页或互动演示。

## 6. 搜索与过滤

搜索覆盖中文、英文、缩写、别名。结果展示类型、简短解释、来源深度和可进入的路径；点击后展开祖先路径。光流/Flow Matching、身份控制/身份一致性、VAE 模型/视频压缩器等同名近义项采用消歧结果。

默认在全库搜索，可切换当前视角或当前子树。实体结果合并多个入口，避免一项技术重复占满结果。

筛选字段：实体类型、视角、应用领域、内容深度；具体模型再提供输入条件和输出模态。不同筛选字段之间 AND，同一字段多选 OR；未知元数据不视为不支持。筛选条常驻并能逐项清除，无结果时明确指出当前约束。

论文或模型的来源年份可筛选；技术概念不要硬套单一“发布日期”。

## 7. 跨视角关联

详情区用明确动词标注关联：采用、研究的问题、评估、相关、阅读前置。相关节点最多先展示少量最有解释价值的条目，其余可展开。点击“从架构视角查看”改变导航上下文，主体内容保持唯一。

可选关系图只呈现当前节点的一跳关系，点击后继续探索。阅读主线仍由大纲与正文承担。

## 8. 示例路径

- 入门用户：任务 → 参考生成 → 身份保留 → 身份控制 → 主体一致性 → 如何评估。
- 算法研究者：范式 → Flow Matching → 骨干 DiT → 时空注意力 → 因果时间依赖。
- 工程用户：训练推理 → 缓存 → KV 缓存 → 因果生成 → 首段延迟与持续吞吐。
- 评测用户：能力 → 物理合理性 → VideoPhy → 测试协议 → 与画质指标的区别。

## 9. 交互验收场景

1. 首次进入能看到全部一级视角；展开根节点仅显示下一层。
2. 只展开大纲不会打断当前正文；点击节点会更新正文和面包屑。
3. 非叶子节点能解释本领域，并给出有区别的子领域入口。
4. 搜索缩写能命中正式名称，结果能定位到三级或四级节点。
5. 同一个共享节点经两条路径打开，主体与来源完全一致。
6. 后退恢复大纲与阅读位置；手机抽屉与键盘操作有明确焦点。
7. 未经核验的模型属性以待核验显示；正文和比较表不会补造性能数字。
