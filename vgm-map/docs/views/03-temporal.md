# 03 时序生成机制

用户问题：模型如何使用过去与未来信息，按什么单位生成，如何继续生成更长视频？

定位：视频专属技术的主入口。以时间依赖和生成策略分类；时空分解注意力移至架构视角，避免把网络结构直接当作时间展开方式。

## 展开大纲

```text
时序生成机制
├── 整段联合生成 Joint / Full-clip
│   ├── 全片段联合去噪
│   ├── 双向时间依赖
│   └── 已知关键帧/未来锚点
├── 因果生成 Causal
│   ├── 逐帧生成
│   ├── 分块生成
│   ├── 历史条件与 KV 复用
│   └── 块内与块间依赖边界
├── 上下文延展 Context Extension
│   ├── 滑动窗口
│   ├── 重叠区与过渡
│   ├── 上下文选择/压缩
│   └── 提示更新与缓存刷新
├── 分层生成 Hierarchical
│   ├── 故事/镜头规划
│   ├── 关键帧或粗序列
│   └── 局部渲染与时间细化
├── 状态与记忆 State / Memory
│   ├── 历史帧、token 与隐状态
│   ├── 持久主体/场景信息
│   └── 世界状态表示（扩展调研）
└── 流式与交互 Streaming / Interactive
    ├── 首段输出与持续输出
    ├── 运行中修改条件
    └── 长序列稳定性与资源边界
```

流式是输出与交互方式，因果是依赖方式，二者可以关联但不等同。整段模型也可能分批解码输出；这本身不能证明生成过程是因果的。

## 必须分别记录的属性

1. 视频时间：实际帧/latent 时间坐标。
2. 生成路径时间：每次去噪或流积分的时间坐标。
3. 生成单位：token、latent 帧、像素帧或块。
4. 单元之间的依赖：是否允许访问未来；已知未来条件是否存在。
5. 单元内部的依赖：分块因果方法可以在当前块内采用双向计算。
6. 训练上下文与推理上下文：来源、长度、噪声程度是否一致。
7. 编码器与解码器的时间依赖：独立于生成骨干记录。
8. 输出方式：何时可见、何时可播放、后续是否会修改已输出内容。

## 详情样例 A：分块生成

实体：`concept.chunk-generation`。

一句话：将视频划分成时间单元，按顺序利用历史上下文生成后续单元。

教学图使用 C1、C2、C3 三块：C2 的生成依赖 C1，C3 的生成依赖可用历史；在每一块内部再展示去噪步骤。正文明确块单位可能是 latent 时间段，而非固定数量的像素帧。

技术区展开块大小、历史窗口、重叠区、缓存与块内掩码。不是所有分块生成都满足严格的逐帧因果性，标签必须注明因果边界。

问题链接：跨块连续性、长期漂移、首段延迟。方法入口：[CausVid](../../research/sources.md#r22)、[Self Forcing](../../research/sources.md#r20)。

## 详情样例 B：训练上下文与暴露偏差

实体：`concept.exposure-bias`。

一句话：训练使用真实历史，但推理需要依赖自己生成的历史，二者的分布差异可能导致错误逐步累积。

显示两条时间轴：真值历史训练、自生成历史推理。Self Forcing 通过训练中的自回归 rollout 使用自生成上下文。[R20](../../research/sources.md#r20)

不要把“Self Forcing”写成所有自回归视频训练的通用名称。其具体监督、截断和少步生成设置属于方法详情，待进一步读全文。

## 详情样例 C：长视频与提示切换

实体：`concept.long-context`，关联方法：`method.longlive`。

一句话：在有限计算与记忆下延长生成，并保持历史内容与新条件之间的连续关系。

LongLive 为阅读提供长序列调优、短窗口、frame sink 和提示更新时 KV-recache 的案例。这里仅根据作者摘要确认机制定位，不把其速度或时长报告外推到其他硬件和检查点。[R23](../../research/sources.md#r23)

展开区按“哪些历史被保留 → 何时淘汰 → 新条件何时生效 → 如何评估长时间漂移”组织。

## 相关方法比较

| 方法 | 本页应突出什么 | 训练推理页的链接 |
| --- | --- | --- |
| Diffusion Forcing | 每 token 的独立噪声水平、条件序列建模 | 噪声与目标设计 |
| CausVid | 双向模型转向因果生成，非对称教师/学生 | 分布匹配蒸馏 |
| Self Forcing | 自生成历史下训练，缓解训练推理差异 | rollout、视频级监督 |
| LongLive | 长序列、窗口与交互提示切换 | 长序列调优、缓存刷新 |

依据：[R20–R23](../../research/sources.md#r20)。这些方法部分机制重叠，不构成互斥的四类。

## 专题页面设计

主图以时间轴和依赖箭头表现“当前生成什么、可访问什么”。视频时间水平排布，去噪步骤在单元内部垂直展开；灰色为已知上下文，强调色为正在生成的单元。

筛选：生成单位、未来信息可用性、上下文跨度、输出方式、条件能否动态更新。禁止只凭“AR”一个标签过滤严格逐帧因果方法。

## 编辑优先级与验收

P0：联合、因果、分块、暴露偏差、滑动窗口。P1：分层、流式、提示切换、持久记忆。P2：显式世界状态和更长时间尺度的交互仿真。

验收：每种路线能画出依赖关系；因果边界明确；长视频时长与长期一致性分开；没有“因果 VAE 自动证明因果生成”的结论；流式指标注明测量对象。
