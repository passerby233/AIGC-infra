# 04 评测与验收

[返回全局架构](../../../README.md) · [上一阶段：模型实验与训练](../03-training/README.md) · [下一阶段：推理优化与发布](../05-serving/README.md)

- **职责**：执行 [01 目标与基准](../01-goals/README.md)确定的比较协议，对模型、Checkpoint 或推理配置进行统一条件下的评测；结合单视频多维人工打分、自动指标与案例分析，提供效果差异、问题定位和验收证据。
- **输入 → 输出**：固定评测集与 case ID、prompt / 条件素材、候选模型与生成配置、评价维度及评分规则版本 → 生成结果引用、逐视频逐维评分与备注、自动指标、模型 / 维度汇总、可筛选的对比案例及验收报告。媒体直接引用 PASS 共享存储，评测员无需重复上传。
- **Infra 用途**：批量生成固定输入和配置；评测平台组织任务与人工打分；指标计算补充质量及耗时、显存、成本证据；评分差异筛选与逐行预览帮助定位视觉 / 音频问题；报表汇总支持算法和业务共同判断效果。
- **项目关联**：评测任务与运行携带 `project_id`，必要时增加 `task_id`，通过稳定 `case_id` 对齐同一输入的不同模型输出；评分、指标和报告关联确切的基准、模型、生成配置、评价规则版本与运行记录，作为[项目生命周期管理](../../platform/project-lifecycle/README.md)中工作项和里程碑的证据。
- **边界**：01 定义任务目标和验收口径，02 提供固定且与训练隔离的评测数据，03 / 05 提供模型及生成执行能力，04 组织评测并输出证据。媒体、算力与通用任务执行复用公共底座，项目结论由负责人确认；评分高、评测任务完成和项目验收通过分别表达。

## 主要 Infra 能力

| 能力 | 输入 → 输出 | Infra 用途 |
| --- | --- | --- |
| 基准执行与批量生成 | 固定 case、条件、模型和推理参数 → 按 case / 模型关联的生成结果、执行状态及性能记录 | 复用 03 / 05 的生成能力，保持版本、随机种子和配置可追溯，区分生成失败与效果不佳 |
| PASS 媒体接入 | 共享存储中的结果路径、素材及索引 → 可读取的评测样本与媒体引用 | 平台通过存储适配读取已有文件，减少重复上传和媒体副本维护 |
| 单视频多维打分 | 单个生成视频、固定评价维度与评分说明 → 各维分数、评测员记录、备注与完成状态 | 算法与业务共同定义维度，评测员独立给单视频打分，再按分数比较不同模型；已有 A/B 模式可保留作为补充 |
| 自动指标与性能评测 | 生成结果、指标配置及执行日志 → 逐样本指标、运行耗时 / 显存 / 成本及失败原因 | 在人工感知之外提供可重复检查的证据；指标工具和版本需明确，评分汇总不能冒充自动模型评审 |
| 对比预览与问题筛选 | 同 case 的多模型输出及评分 → 逐行媒体 / 分数对照、指定维度的优劣案例与问题集 | 筛选“A 在某维度高于 B”的案例，结合 prompt、条件素材和备注观察 B 的具体退化表现，复用 DataViewer 浏览能力 |
| 汇总报表与验收证据 | 同一协议下的有效评分、指标、覆盖率和问题集 → 维度汇总、分布图、模型对比和报告引用 | 后期自动生成报表，辅助算法与业务定位差异；保留样本数量、缺失项及明细入口，避免只看总分 |

视频质量可关注提示词遵循、主体一致性、时间闪烁、运动、画面质量；音视频任务还可关注声音质量、参考内容保持和音画配合。Jira 附图中的 1–5 分及维度图表示参考，具体维度、分值、权重与验收门槛由项目确定并版本化。自动视频指标的补充参考为 [VBench 官方项目](https://github.com/Vchitect/VBench)，不据此指定必须采用的工具。

## 项目关联与证据流转

一次评测应能追踪“项目 / 工作项 → 基准版本 → case → 模型与生成运行 → 人工评分 / 自动指标 → 对比报告 → 负责人结论”。模型标签仅用于展示，正式比较绑定真实模型 / Checkpoint 和推理配置版本；同一 case 的多次生成需保留各自的结果标识。

评价维度即使低频变更，也要保存评分规则版本。正式对比使用相同基准、输入条件和可比较协议；缺少输出、评分不完整、不可访问的样本单独统计。评分差异默认基于同 case、同维度、同评分口径，不能把未评分样本当作 0 分。

原始评分、指标与任务事实由评测平台维护，生成日志由执行平台维护，媒体由 PASS / 存储维护；工作台采集版本引用与摘要。分别展示生成 / 评测进展、自动验收结果、最近同步时间及负责人确认的项目状态。报告可作为模型选型、推理优化回归与交付里程碑的证据；不满足要求时输出问题集，回到 02、03 或 05 处理。

## 与共享能力的边界

- **DataViewer**：复用媒体渲染、同 case 多模型对照和失败案例浏览；评分维度、任务组织、评分记录及统计口径由评测平台维护。后续先检查 Prim Eval 可复用的浏览能力，再补充适配。
- **公共技术底座**：提供存储访问、任务队列、算力、日志及权限；本模块定义评测业务规则和结果协议，不另建通用生成服务或媒体库。
- **生命周期管理**：组织跨团队工作项、里程碑与交付决策；本模块给出可追溯证据及差异分析，自动规则与 Agent 可提出建议，负责人确认验收和项目推进。
- **性能与质量**：生成平台产出性能事实，04 按相同条件比较；05 改变输出的量化或配置优化需重新评测。人评、自动质量指标、性能结果分别保留，未经定义不混成一个总分。
