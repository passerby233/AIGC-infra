# 内容模型与分类边界

## 1. 七个视角是导航投影

网站以七个视角提供入口，每个视角内部展示一棵便于阅读的大纲；底层保留共享实体与关系。导航树用于组织阅读，不宣称给出唯一或严格互斥的学科分类。

一个方法可以同时采用扩散生成、因果时间依赖和 Transformer 骨干。把它只归入一个目录会丢失信息；为每个目录复制正文又会产生内容漂移。应让多个导航入口指向同一实体。

建议的默认层级是：视角 → 子领域 → 技术概念 → 有必要时的细分。详情页内的原理、公式、局限和案例属于阅读章节，不能全部转成分类子节点。

## 2. 实体类型

| 类型 | 含义 | 示例 | 展示规则 |
| --- | --- | --- | --- |
| view | 用户选择的观察角度 | 时序生成机制 | 七个固定一级入口 |
| category | 为阅读组织的子领域 | 推理加速、运动控制 | 自身有概览与子节点 |
| concept | 可独立解释的技术概念 | Flow Matching、因果注意力 | 正文唯一，允许多入口 |
| task | 输入输出或处理目标 | 图生视频、视频编辑 | 显示输入、输出、保留约束 |
| method | 特定论文提出的方法 | Self Forcing、TeaCache | 绑定来源与适用范围 |
| model | 具体模型或模型系列 | CogVideoX、Wan | 系列与具体检查点区分 |
| capability | 希望达到的表现 | 身份一致性、物理合理性 | 与测量方法及失败案例连接 |
| benchmark | 评测协议或集合 | VBench、VideoPhy | 记录任务、提示集、协议版本 |
| metric | 具体计算指标 | FVD | 说明方向、输入和局限 |

论文在独立来源目录中维护，实体通过 source_ids 引用。首批 JSON 使用 concept、task、method、model、capability、benchmark、metric；view 和 category 由导航结构表达。

## 3. 关系与证据

| 关系 | 方向 | 使用条件 |
| --- | --- | --- |
| adopts | 方法/模型 → 概念 | 原论文或官方实现明确采用 |
| addresses | 方法 → 问题/能力 | 作者明确研究该问题，不等于已完全解决 |
| evaluates | 基准/指标 → 能力 | 评测协议覆盖该维度 |
| related_to | 概念 ↔ 概念 | 用于阅读关联；不暗示性能优势或因果 |
| prerequisite | 概念 → 前置概念 | 教学顺序建议，标注为编辑判断 |

导航包含关系由视角 sections 的 entity_ids 表达，不再作为技术事实关系存储。方法/模型案例通过 example_ids 单独呈现。关系至少包含来源 ID 或 editorial 标记；没有实验支持时不能把“相关”写成“提升”或“解决”。

## 4. 必须保留的边界

| 容易混淆的对象 | 处理方式 |
| --- | --- |
| Diffusion 与 DiT | 前者是生成建模框架，后者是骨干设计；分属范式和架构。[R12](../research/sources.md#r12)、[R16](../research/sources.md#r16) |
| Flow Matching、Rectified Flow 与一般 flow 模型 | 导航允许并列阅读，正文解释学习目标、路径与可逆流的联系；不把它们画成完全互斥集合。[R14](../research/sources.md#r14)、[R15](../research/sources.md#r15) |
| VAE 生成建模与视频 VAE | 范式页解释潜变量建模；架构页解释压缩与重建。使用 VAE 的扩散模型不能据此整体标为 VAE 范式。[R11](../research/sources.md#r11)、[R13](../research/sources.md#r13) |
| 自回归与因果生成 | 前者描述条件分解，后者描述时间依赖；必须说明自回归单位是 token、帧还是块。|
| 因果 VAE 与因果生成器 | 编解码器的因果性与生成骨干的因果性分别记录。[R04](../research/sources.md#r04)、[R05](../research/sources.md#r05) |
| 分解式时空注意力与时序生成顺序 | 注意力连接结构放架构页；时间依赖和输出顺序放时序页。|
| 图生视频与参考生成 | 图生视频说明输入合同；参考生成强调身份、主体或风格保留。同一任务可能同时具有两种标签。|
| 控制信号与控制效果 | “输入轨迹”不等于“轨迹准确执行”；机制在控制页，效果在能力页。|
| 少步采样、蒸馏与流式生成 | 分别涉及数值求解、训练转换和输出方式；不能互相替代。|
| KV 缓存、去噪特征缓存与 VAE 特征缓存 | 分别说明复用的计算、有效条件及刷新策略，避免共用一份模糊定义。|
| 光流与 Flow Matching | 前者是帧间运动表示，后者是生成建模训练框架；搜索必须消歧。|
| 视频生成与联合音视频生成 | 输出模态是独立字段；单独生成配音与联合建模分开说明。|

## 5. 元数据规范

实体最少保存稳定 ID、类型、中英文名称或别名、一句话说明、所属导航入口、source_ids、evidence_status、文档位置。不要把路径写进实体 ID，否则调整目录会改变实体身份。

研究细节逐步补充：假设、输入/输出、代表工作、适用范围、失败模式、比较维度、最后核验日期。

模型条目增加系列名、具体版本/检查点、输入条件、输出模态、公开状态和证据范围。未知值保留 unknown，不能从模型名称推断。

实验条目增加硬件与设备数、精度、分辨率、帧数及 FPS、采样步数、批大小、测量起止范围、基线、随机种子与协议版本。数字只有具备这些背景才适合比较。

## 6. 来源深度与内容状态

- abstract：阅读作者摘要页，可以支持核心贡献与任务定位；不支持声称完成实现级核验。
- targeted_sections：额外阅读特定论文章节，记录章节范围。
- official_readme：阅读作者或机构仓库说明；不等于代码审计或运行复现。
- editorial：阅读顺序、页面组织或教学简化，由本设计提出。

来源的新旧、权威性和读取深度分别记录。综述支持覆盖范围和分类视角，技术定义尽量回到原论文。具体方法的效果保留为作者报告，本轮不作实验复现结论。

## 7. 结构化索引约定

[knowledge-map.json](../data/knowledge-map.json) 的 entities 是共享主体，views 是导航投影，relations 是有标注的跨节点关联。七篇专题文档包含更完整的扩展大纲；索引明确标为 core_seed，不把未录入索引的方向当作不存在。

验收要求：实体 ID 唯一；导航与关系引用有效；来源 ID 能解析；同一实体经不同入口访问时正文相同；应用领域只作为标签；设计建议与文献事实可区分。
